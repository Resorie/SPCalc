# SPCalc · 卫戍协议伤害计算器

面向《明日方舟》卫戍协议的单干员与团队配置比较工具。选择干员、初始或精锐状态、潜能、自持有练度、技能、两件装备和盟约条件，对比相同目标与时间下的累计伤害、平均 DPS、伤害类型和技能时间线。

**当前是试验版：目标是原活动规则，数值由固定版本的非官方复刻引擎产生，尚不等于原版实测。** 界面布局参考 [Closure Wiki](https://closure.wiki/zh-cn)，未复制该站代码或美术素材。

## 使用

需要 Node.js 22 或更新版本。无需安装 npm 依赖或后端；地图所用的固定版本 PixiJS 与 Three.js 已随静态资源打包。

```sh
npm test
npm run build
npm run dev
```

默认本地地址为 `http://127.0.0.1:4173/`。`npm run build` 将网站复制到 `dist/`，所有资源使用相对路径，支持 GitHub Pages 的仓库子路径。`node scripts/serve.mjs dist` 可预览发布产物。部署工作流位于 `.github/workflows/pages.yml`，GitHub Pages 的构建来源需设为 GitHub Actions。

干员、装备、盟约使用可搜索的图标网格选择，图片缺失时保留名称。头像采用基础头像以保持跨形态辨识，初始／精锐由文字标注；普通／进阶装备可能共用原图，进阶另有标记。

配置自动保存在当前浏览器，可用「载入默认方案」恢复该版本的初始比较；“复制配置链接”包含当前全部方案、目标条件、数据版本和引擎提交号。逐秒 CSV 与结果 JSON 可用于进一步分析。计算结果不会发送到服务器。

## 数据与规则

- 单人和团队靶场默认使用「卫戍协议·规程・序列Ⅰ」V3_1，规则包在 `data/act3autochess-v3_1/`。它包含 141 名可选预置干员、自选干员、26 个盟约及 10 张启用地图，清单记录来源与逐文件 SHA-256。
- 默认引擎为 [Stronghold-Protocol 0.4.0](https://github.com/sganggs/Stronghold-Protocol/releases/tag/v0.4.0) 的 `55f528e9fc4872388360ee85e13eca8594856204` 提交。战斗代码与共享模块在 `vendor/stronghold-regulation/`，浏览器内存数据加载器负责安装已验证的数据与数值上界。
- 旧版分享链接继续绑定 V2_2 与其原有引擎，版本间独立保存浏览器内的方案。规则包目录与默认版本见 `data/catalog.json`。
- [PRTS 规程盟约记录](https://prts.wiki/w/卫戍协议·规程/PRTS盟约记录) 可用于对照本期干员特质和盟约效果。

计算从干员部署时刻开始，每秒 30 帧，保留上游的技能自动释放逻辑及初始操作冷却。设测试时间为 $T$、实际扣血总量为 $D$，平均输出为 $D/T$，包括启动与技能空窗。元素损伤累积不是生命伤害，只有实际扣血进入统计。多目标时汇总各目标扣血。

## 单人模式的当前边界

- 支持预置干员及当前快照中有技能实现的自选干员。可选条目由每个版本的自选池和原型限制决定。自选可选等阶、初始／精锐、技能及该形态允许的模组，无卫戍专属特质，保留阵营盟约。原型干员按复刻规则锁定技能和模组，不享受持有潜能、练度加成。预置干员可切换该棋子的模组或选择不携带。模组在精锐棋子上按数据包指定的等级生效。
- 靶子初始位于干员正前方指定格，不行走、不主动攻击；每个靶 10 亿生命、元素抗性 0，无控制免疫。重量和地面／空中可调；规程默认面板参考假想敌：茧，防御 800、法抗 30、重量 9、地面。多个靶在同一点。推拉等技能仍可移动靶子，结果中会提示。
- 领袖选项只改变敌人分类，不等同于真实首领战；不包含具体首领技能、共享血量或终局单次伤害上限。
- 盟约人数是外部激活条件。单人方案激活灵巧后按相邻队友覆盖，为被测干员计算全程攻速光环。装备、特质、自动召唤物与战斗中层数变化按引擎结算，完整阵型需在团队靶场布置。
- 装备栏仅展示战斗可携带装备，排除使用后销毁的道具和未实际开放的进阶占位记录（如变形同构体）。消耗道具的层数、晋升等结果需直接设置，本工具不重演休整期；旧配置若携带了这些记录会要求更正，不会静默删掉。
- 两个装备槽可以佩戴同款装备。百分比加攻等同类属性先求和，精准狙击镜按每件装备的倍率分别乘算。
- 固定随机种子确保同配置复算，不提供数学期望、方差或置信区间。单种子不能支持小差异配置的统计结论。
- 泛用技能实现会提示；上游其余 `[ASSUMED]` 和刻意偏差依然存在，不能据此声称全干员已与原版一致。
- 伤害日志最多保留 10000 条，界面显示前 60 条；累计伤害、逐秒曲线不受日志截断影响。

规程版补充了麒麟R夜刀、焰狐龙梓兰的可自选数据、头像及专用战斗实现。两个等阶均支持三技能和本期允许的模组、潜能。源数据与动画素材包校验值见 `data/act3autochess-v3_1/collab.json`，技能在 `src/adapters/operators/`。灰烬等其余五名联动自选仍可搜索，当前显示「暂无战斗实现」。

夜刀二技能使用客户端动画的 16 个命中时点，三技能使用连续碰撞和命中后的延长。焰狐龙梓兰按每轮箭矢消耗强击瓶，并按技能动画处理连射、起飞和落地。现有靶场没有手动撤退或选择下一次部署点，翔虫机动的再部署加攻只由实际再部署触发。现有引擎以格子和受击体积近似部分弹道位置、控制和前后摇，技能伤害尚未逐项做官服录像校准。

## 输出归属

`src/damage-ledger.js` 独立接收实际扣血事件，以玩家 ID + 棋子 UID 标记干员实例。同名干员不会合并；召唤物沿 `ownerUnit` 找到所属干员，再按引擎提供的伤害归属计入；未知来源单列。总输出 = 各干员输出之和 + 未归属伤害，召唤物不重复计数。增益提供者不会获得被辅助干员的伤害份额。

结果 JSON 中 `damageByOperator` 提供每个实例的本体／归属伤害、召唤物伤害、总量及类型；每秒样本带有 `operators` 分项。单人和团队靶场共用归属统计；团队入口为 `team.html`。

## 验证

`npm test` 包含基础伤害与原有靶场回归，以及自选等阶／形态／技能／模组、予愿安洁莉娜和叙拉古、目标重量与空中目标、消耗品／虚假进阶拒绝、同名实例及嵌套召唤物归属、跨版本运行隔离、数据哈希校验和旧配置迁移。自选目录全部可选条目在两个形态各运行 8 秒用于发现接口错误，不代表已经覆盖所有技能周期或与原版一致。

PRTS 核对依据：[卫戍协议](https://prts.wiki/w/卫戍协议) 的甄选干员、核心盟约与特质说明；[予愿安洁莉娜](https://prts.wiki/w/予愿安洁莉娜) 的隐藏势力叙拉古、天赋和技能说明。详细战斗代码仍沿用复刻，含其原有假设，尚未逐项进行官方实测校准。

## 版本数据与引擎分离

- `data/catalog.json` 只登记可用版本及默认版本。
- 每个 `data/<版本 ID>/manifest.json` 声明数据修订号、数据格式、对应引擎 ID、来源、各 JSON 的 SHA-256 和默认配置。加载时逐文件校验；导出的配置和结果固定数据版本、修订及引擎组合。
- `src/rulesets.js` 加载数据包，不包含干员公式；`src/engine.js` 根据注册的引擎 ID 选择适配器。数据文件不能指定任意脚本执行。
- `vendor/stronghold` 保留盟约版固定引擎，`vendor/stronghold-regulation` 保留规程版固定引擎；适配器负责把靶场配置转为战斗输入。基础属性、技能参数、盟约层数参数等在 JSON 中；技能事件、特殊触发和结算顺序仍是引擎代码。新机制需要新增或修改对应实现，不能承诺只换数据即可兼容。
- 每次模拟重新安装所属数据包；同一线程同步调用。浏览器使用独立 Worker 顺序计算方案，不把上游的全局数据缓存当作并发安全接口。

更新步骤见 [docs/更新版本.md](docs/更新版本.md)。旧版配置链接会请求它记录的版本；若该版本已不在部署目录中，会停止并提示，而不是静默套用默认版本。继续保留盟约版的单人和团队规则包，未提供赛季切换界面，也没有自动监控 PRTS。

## 技能期间 DPS

按引擎技能开始／结束事件取生效区间，采用左闭右开区间，测试结束时截断尚未结束的技能。技能期间实际扣血总量除以生效总时长，多次释放按总时长加权；包含同期普攻、装备和召唤物，不是仅技能自身的增量伤害。延迟命中按扣血时间归类，区间外的持续伤害不计入。瞬发或未开启技能没有正长度区间，显示“—”。按时间聚合全部扣血事件，统计不受伤害日志条数上限影响。结果 JSON 的 `skillWindow` 包含时长、伤害、DPS 和区间。

## 外部加成与多方案

可用＋复制当前方案，保留 1–5 个独立方案，全部在同一目标条件下计算。图表、时间线、JSON 与 CSV 包含全部方案；相对提升以方案 A 为基准。外部加成全程作用于该干员，每次再部署重新施加同名替换增益，不直接赋予召唤物；召唤物仅按原机制继承。攻击百分比采用加算乘区，基础固定值先参与百分比、后加固定值随后加入，最后乘独立倍率和培养系数。攻速填写点数并遵守引擎上限。这些手填外部属性不模拟提供者的站位或触发时机；团队实际队友的效果另按布阵结算，不能将手填常驻加成等同于完整队伍模拟。

## 单人靶场的奥术假设

规程版按成员的实际伤害事件触发奥术附伤，3 人档按命中累积减法抗。盟约版分享链接仍采用当时的全程覆盖规则，3 人档按目标半血以下强化结算。覆盖假设在结果 JSON 的 `assumptions` 字段中。

## 单人靶场的突袭假设

激活突袭且干员是突袭成员（包括变形同构体转职）时，地面靶改为固定位置，干员在远处背向靶子开始战斗，覆盖前方距离输入。由原有突袭轮询判断技能就绪或 10 秒未攻击，再按原规则完成撤退、保留技力再部署及加攻；不在零秒预先赋予突袭属性。落点由引擎选取，确保可以攻击地面靶。测试时间不足则不会提前跳跃。非成员和空中靶沿用普通靶场。跳跃事件写入 `timeline` 和结果假设中的 `deployments`；之后仍保留技能退场等实际机制。

## 团队靶场

打开 `team.html`，或从单人靶场的“团队靶场”入口复制现有方案。每队 1–9 名干员，最多 5 个整队方案，共用原版地图、靶子和时长；费用、人口、整备、手动放置召唤物和敌人波次不模拟。默认示例为烛煌、焰影苇草、史尔特尔，示例没有预填高层盟约，也不保证维持技能不倒地。

当前 `data/catalog.json` 的 `teamDefault` 指向 `act2autochess-v2_2-team1`，补充 8 张启用地图，原数据文件字节与单人旧包相同。旧包保留，单人旧链接继续加载原版本。新的地图也须加入版本清单和 SHA-256 校验；UI 不写死下个赛季的地图目录。地图采用 Boss 场地区域及左方部署区，保留地形、活动机关和引擎已有的环境效果，不将不合法棋子自动搬走。默认 Boss 受击范围为 5×3、中央占地 3×3，沿用上游大体型命中判定，同一攻击不会因覆盖多格重复结算。命中框只作为独立覆盖层，不把两侧禁部署块改成路面；两侧部署仍取决于原图地形。默认锚点为 (3,10)，与中央三行地板对齐。此前默认 (2,10) 的配置保留其位置，并提示使用「Boss 归位」修正；归位保留所有队员，位置冲突要求手动处理。

地图复用 Stronghold-Protocol 0.4.0 的 `BoardScene`、`TileField`、相机、材质与场景加载模块。规程的十张地图由官方 Windows 客户端资源的三个子场景提取，按上游工具合成。地图和贴图按需加载，切图时使用序号防止旧场景覆盖当前选择。旧版地图场景也保留。客户端版本、原资源包 MD5 和文件 SHA-256 可在各地图包的 `provenance.json` 中查看。

3D 使用上游 Three.js 渲染，地块高度、合法部署／射程高亮、机关与地形动画使用上游 PixiJS 层；缺少 WebGL2 时自动使用同一上游的棋盘渲染，`?map=2d` 可显式进入兼容模式。完整 3D 场景的视野限定在 Boss 区域；镜头使用上游相机模型按面板尺寸取景，关闭额外实时阴影，保留场景烘焙光照。干员仍为头像标记，不包含战斗模型、技能动画或回放。为减少开销，地图以最多 30 FPS 绘制，滚出可见区域或页面隐藏时暂停绘制；减少动态效果设置下不推进动画。

`displayGrid` 保留原图，计算地图只叠加 Boss 中央禁部署标记，并保留原始 tileKey、高度、通行与特殊地形属性。地图工具栏、队员卡、朝向菜单及手机编辑面板统一使用计算器的主题变量，场景自身保留上游游戏画面。

添加干员后点击绿色空格部署；棋子或下方队员卡可拖放，也可点选后点击地块。放置后选择朝向，R 旋转，Esc 取消，Ctrl/⌘ Z 撤销。点击队员卡编辑装备等配置，窄屏打开底部面板。橙色显示基础射程，动态射程由战斗结算。地图设置沿用现有选择器。

计算接口 `simulateTeam(team, target, scene)` 和 `validateTeam(team, target, scene)` 接收 `team.members`（稳定 uid、config、row、col、dir）、`team.bonds`（id、layers、可空的 count 覆盖值）、`team.assumptions`（arcane、raid）、`scene`（stageId、targetRow、targetCol、targetShape）；Boss 坐标为受击区最下行的中间列。全部队员进入同一场 Battle，治疗、状态、元素和弹药事件真实共享。盟约默认按干员去重统计，计入转职、调和与精锐计数；覆盖人数不生成隐藏队友。

团队规程版的盟约默认按真实阵型触发，可以单独开启突袭预设接敌。奥术全覆盖选项适用于盟约版分享链接。突袭简化只为突袭成员匹配合法远离靶子的初始空格和朝向，保留原本的触发等待及再部署；没有合法起点／落点时停止计算。结果记录采用的假设。靶子在初始部署前入场，因此部署时技能能作用于靶子。

配置 schema 3 保存团队方案；团队本地存储与单人分开。单人转入时复制每个方案的一名队员，保留团队盟约为手动覆盖，关闭简化并提示调整布阵，不将旧版输入静默改为团队。`damageByOperator` 包含逐人总伤害、召唤物、平均 DPS、技能期间 DPS；`samples` 提供逐秒个人／全队累计伤害。辅助者不重复得到队友伤害。CSV 包含每个方案的全队、个人和未归属伤害；JSON 使用产生结果的输入快照，避免编辑后把新配置与旧结果混在一起。诊断事件单类最多保留 2000 条，仅用于调试，不是完整治疗／弹药统计面板。

单人及团队计算均在独立模块 Worker 中运行；团队方案顺序计算。团队可取消，计算期间改变配置会丢弃过期结果。仍为固定随机种子的复刻结果，不能视为官方数值校准，也不能承诺强治疗配置下所有单位必定不倒地。
